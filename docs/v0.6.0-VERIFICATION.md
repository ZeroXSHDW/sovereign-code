# v0.6.0 live verification checklist

The task-packs and MLX features are written and CLI-wired. What remains is
proving them on real hardware, not writing more code. Run these in order and
check each box only after the command succeeds end to end.

Every step is `make check`-clean first (already true), so the work here is
evidence, not implementation.

## MLX server (`sovereign mlx`)

A live MLX server needs the mlx-lm virtualenv and at least one set of weights.

1. [ ] `sovereign mlx status` reports the state file, port, and whether a
       server is supervised, and exits 0 without a server running.
2. [ ] `sovereign mlx models` lists the MLX catalog with downloaded vs.
       not-downloaded state (no models yet is a valid first result).
3. [ ] `sovereign mlx pull --model mlx-qwen3-4b-4bit` downloads the smallest
       catalog model and reports its size beforehand.
4. [ ] `sovereign mlx start --model mlx-qwen3-4b-4bit` starts a supervised
       server; `sovereign mlx status` now shows it online with a PID.
5. [ ] Record the measured speed: two turns through the gateway with the MLX
       model warm, noting tok/s (expected ~69 tok/s without a draft, higher
       with the 0.6B draft). This is the number the README quotes.
6. [ ] `sovereign gateway-config --apply` merges the `mlx-*` aliases into the
       LiteLLM config with a timestamped backup, without touching existing
       aliases or fallbacks.
7. [ ] `curl 127.0.0.1:4010/v1/models` now lists `mlx`, `mlx-code`,
       `mlx-balanced`, `mlx-fast`, `mlx-chat` and the downloaded tag.
8. [ ] `sovereign mlx stop` shuts the server down and `sovereign mlx status`
       confirms it is offline with no orphaned PID.

## Task packs (`sovereign pack`)

Needs at least one installed model the router can pick for the pack's domain.

9.  [ ] `sovereign pack list` prints all eight packs with domain and summary.
10. [ ] `sovereign pack show pentest` prints guardrails, steps, and matching
        skills — and the steps stop at a SCOPE-file requirement.
11. [ ] `sovereign pack brief pentest --path <tmp>/AGENTS.md` writes the
        managed `sovereign-pack:pentest` block; running it again replaces the
        block instead of duplicating it.
12. [ ] `sovereign pack models forensics` shows an installed router pick for
        the domain (or a clear "pull X" suggestion when none is installed).
13. [ ] `sovereign pack verify <key> --model <installed-tag>` runs the probe
        and records a pass in the verification file; re-running is idempotent.
14. [ ] `sovereign pack install pentest --target opencode` installs the pack's
        skills once; `sovereign skills` reports the increased install count.

## Gate

15. [ ] `make check` still green after the live runs (unchanged code, but the
        evidence must not regress the suite).
16. [ ] Update `docs/ROADMAP.md`: move these two "Next — v0.6.0" items from
        "remaining: live run" to done, with the measured tok/s number from
        step 5 recorded.

## Why this is a list, not code

Each item maps to a `sovereign` subcommand that already exists and is unit
tested. The gap is only that nobody has run them against a real MLX server and
a downloaded model. Filling these boxes converts "implemented" into "verified"
without adding a single line that might collide with the coding loop's work.
